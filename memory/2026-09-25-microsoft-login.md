# Microsoft sign-in investigation

- Symptom: selecting Microsoft either opened the generic Keycloak login page or showed Keycloak's “Unexpected error when authenticating with identity provider” page.
- Root cause: Keycloak's Microsoft broker was configured without its `tenantId`, so Keycloak used Microsoft's `/common` endpoint. The recording and Keycloak callback both showed `AADSTS50194`: the Entra application is single-tenant and cannot use `/common`.
- Data issue: the live workspace policy initially stored `imsahadeb@gmail.com` as `microsoft_tenant_id`; this was replaced with the Entra Directory (Tenant) ID `449ef8af-d2d1-43ec-bdfe-a448d2d2e5a7`. The next callback reached Microsoft but returned 502 because the live Keycloak provider contained a ten-character masked placeholder instead of the client secret. The local Keycloak provider now has the real secret value supplied by the operator.
- Fix: pass the persisted Entra directory ID into Keycloak's Microsoft IdP config, reuse the stored client secret when settings are saved without a replacement secret, re-provision valid providers at boot, and add a client access-token mapper for the broker alias. Invalid directory IDs now fail clearly instead of creating a `/common` provider.
- Callback fix: the NextAuth Keycloak callback now forwards the broker access token. The backend introspects it, verifies issuer/client/subject/expiry and the signed broker alias, re-checks the tenant policy and IdP configuration, then reuses the verified token rather than trusting posted email data or resetting a password.
- UX/config fix: Microsoft login always waits for the tenant policy, sends `kc_idp_hint=microsoft-<workspace-id>`, and is disabled with an explanation until a valid Entra Tenant ID is loaded.
- Secret handling: the current `tenant_auth_settings.microsoft_client_secret` column is a plain text `VARCHAR/TEXT` value; the application masks it only in the UI and does not encrypt it before persistence. Keycloak also keeps the broker credential in its provider configuration. A server-held encryption key or a secret manager is needed for encryption at rest.
- Verification: backend build passed; all 11 backend suites passed (40 tests); Microsoft frontend regression tests passed; frontend TypeScript check passed. The live Keycloak authorization request now targets the tenant-specific Microsoft endpoint and includes the broker mapper.
- Required operator action: save the full client secret in Workspace Authentication & SSO (the UI must not receive the masked placeholder), then restart/redeploy the backend so the compiled service loads the fix. Rotate the exposed Entra secret after testing because it was shared in chat.
